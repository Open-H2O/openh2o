# Open Water Accounting Platform - Scheduled Jobs
#
# Install:   make install-cron
# Verify:    make show-cron
#
# `make install-cron` copies this file into the schedule, and writes two lines of its
# own above the jobs, so this file needs no edit:
#   OPENH2O_DIR      this checkout (the folder holding docker-compose.yml)
#   OPENH2O_LOG_DIR  where the jobs write their logs: $HOME/openh2o-logs, or the folder
#                    named on the command line (make install-cron OPENH2O_LOG_DIR=/path)
# When OPENH2O_NTFY_URL is set in .env or in the environment, it writes that line too.
#
# Jobs:
#   run-sync.sh    - Resilient external-data sync (ensures container is up,
#                    logs to a writable path, alerts via ntfy on failure if
#                    OPENH2O_NTFY_URL is set).
#                    Live gauges (CDEC, USGS) run hourly for near-real-time flow;
#                    slower sources (groundwater, climate) run once daily
#                    because they only publish daily/periodically.
#   run_accounting   - Nightly 3:30 AM: calculate every reporting period that is not
#                      finalized, month by month, so figures follow the day's new
#                      data. Never touches a finalized period. Writes a record the
#                      period page and Site Health read.
#   backup.sh        - Nightly 1:25 AM: dump the database (checked by reading it back) and
#                      the uploaded files into backups/ in the checkout, keep the newest 14
#                      of each, and alert via ntfy on failure if OPENH2O_NTFY_URL is set.
#                      Copy backups/ to another disk or computer as well. Restore with
#                      scripts/restore.sh.
#   run_health_checks - Check database, disk, SSL, migrations, and sync freshness
#   prune_old_data    - Delete staging records and logs older than retention thresholds

# Hourly: live stream / reservoir telemetry (near-real-time flow & stage)
0 * * * * $OPENH2O_DIR/scripts/run-sync.sh cdec usgs

# Daily 1:25 AM: back up the database and the uploaded files, before the sync and the
# accounting run touch anything. A dump that cannot be read back fails and alerts.
25 1 * * * $OPENH2O_DIR/scripts/backup.sh

# Daily 2:00 AM: slower periodic sources: groundwater (DWR WDL/SGMA), climate (NOAA) and
# CIMIS. CIMIS is fetched when its key (CIMIS_API_KEY) is set; with no key it is skipped
# in one line. One source failing does not stop the others, run-sync.sh goes on to the next.
# CNRFC is switched off in OpenH2O's list of data sources (it publishes forecasts, not
# readings), so the schedule does not fetch it. OpenET is not a station source: its figures
# are fetched by `sync_openet_parcels`, which nothing here schedules, so run it by hand
# when you want figures for new months.
0 2 * * * $OPENH2O_DIR/scripts/run-sync.sh dwr_wdl dwr_sgma noaa cimis

# Daily 3:30 AM: calculate every open reporting period, after the 2:00 AM sync has
# brought in the day's data. A finalized period is skipped, never changed. One run at a
# time: if a person pressed the button and it is still going, this one waits its turn.
30 3 * * * cd $OPENH2O_DIR && docker compose exec -T web python manage.py run_accounting --open-periods --trigger schedule >> $OPENH2O_LOG_DIR/calculation.log 2>&1

# Health checks every 6 hours
0 */6 * * * cd $OPENH2O_DIR && docker compose exec -T web python manage.py run_health_checks >> $OPENH2O_LOG_DIR/health.log 2>&1

# Monthly data pruning on the 1st at 3:00 AM (--confirm required; default is dry-run)
0 3 1 * * cd $OPENH2O_DIR && docker compose exec -T web python manage.py prune_old_data --confirm >> $OPENH2O_LOG_DIR/prune.log 2>&1
