{% comment %} Recharge overview map: every recharge site the list is showing, on the recharge:list overview page. The Bucket-3 overview map (see docs/2.0-UX-PATTERN-SPEC.md) for the recharge screen — the recharge analogue of the Zones boundary map and the Surface Diversions point map. Recharge sites are MIXED geometry: most are polygon basins, some are single points. So this map draws both, exactly as the big district map does (templates/geography/map.html): one GeoJSON source from recharge:sites_geojson (which already carries pk in properties), with a fill+outline pair filtered to non-points and a glow+circle pair filtered to points. Clicking either opens a popup with the site name and a link to its full detail page. Modeled on _zones_overview_map.html. The overview map card (143-07, designed on Surface Diversions and copied here). Three things beyond the marks: * An always-on label per SITE, not per polygon part. A symbol layer placed directly on the fill/outline source would repeat a multi-ring basin's name once per ring; instead a SECOND client-side source, `{{ map_id }}-labels`, carries one Point per site at that site's bounding-box centre (built from the same coordinate walk the fitBounds calculation already does), and OH2O.addDetailLabel draws it with anchor: 'center' so the label sits over the basin rather than offset from a dot that is not there. * The map FOLLOWS THE LIST. The results partial emits the whole filtered queryset's pks as json_script#results-map-pks, and OH2O.followResults filters the fill, outline, glow, dots AND the label layer here to those pks and re-frames on first paint and after every htmx swap of #results. The geojson endpoint takes NO parameter: one fetch per page load, one source, filtered client-side. * The card's head (partials/_map_card_head.html) carries the count line and the key; the map itself says nothing in words.
