What the by-ET file holds

The by-ET file is OpenH2O's GEARS file of groundwater extraction estimated from crop ET. The by-well file is OpenH2O's other GEARS file, of meter readings.

Each line of the by-ET file is one well and one month. The Measurement Method column reads "Unmetered/Estimated". For a use area linked to a well, in a month a meter reading does not cover, the estimate is the month's ETAW met by groundwater divided by the use area's irrigation efficiency. A month calculated before OpenH2O began keeping the estimate does not have one. The file counts that month at its ETAW met by groundwater, without dividing by irrigation efficiency. A use area linked to one well puts its whole estimate on that well. A use area linked to more than one well has its estimate divided among those wells by the shares on the wells' pages, so the use area is counted once.

OpenH2O records a month's crop ET when OpenET sends it. OpenH2O's monthly calculation then makes the estimate. A month recorded and not yet calculated does not have an estimate yet.

The by-ET file leaves out use areas not linked to a well. For each use area, the by-ET file leaves out the months a meter reading covers, which the by-well file reports, so a use area's month is in one of the two files at most. The by-ET file also leaves out months OpenET has not yet sent crop ET for, and months OpenH2O has recorded and not yet calculated.

The card headed Validation warnings on this page gives the number of use areas left out because they are not linked to a well. The checks do not name those use areas.
