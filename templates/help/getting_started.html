How to set up OpenH2O

Run the Setup Wizard →{% endif %}		 The Setup Wizard uses a boundary: the outline of the land your records cover. Upload the boundary as a zipped shapefile, a KML file or a GeoJSON file, or type the north, south, east and west edges of a rectangle around the land. Or choose Start without one, and come back to the boundary later. The wizard uses the boundary to bring in the groundwater subbasins{% if 'parcels' in enabled_modules %}, parcels{% endif %}{% if 'datasync' in enabled_modules %}, streams and monitoring stations{% else %} and streams{% endif %} inside it and nearby. You choose which of these to bring in before it starts. The subbasins{% if 'parcels' in enabled_modules %} and parcels{% endif %} come from the California Department of Water Resources, so the wizard finds none outside California. {{ steps.use_areas }}Import your use areas Water accounting > Use Areas
Go to Use Areas →		 OpenH2O keeps its records by use area. Each parcel is one use area. {% if 'setup' in enabled_modules %}The Setup Wizard downloads the parcels that overlap your boundary from the California Department of Water Resources’ parcel map and saves each as a use area. The map covers California only. You can give the wizard a list of Assessor Parcel Numbers (APNs). The wizard then saves only the parcels on that list. The wizard’s result counts each parcel it leaves out for lack of a parcel number or a readable outline. Use Import use areas on the Use Areas page to load your own parcel file instead.{% else %}Use Import use areas on the Use Areas page to load your parcel file.{% endif %} The file can be a zipped shapefile, a KML file or a GeoJSON file. The preview counts the new use areas and those it leaves out: already on file, outside your boundary, or without a parcel number or an outline OpenH2O can read.

Go to Wells →		 {% if 'infrastructure' in enabled_modules %}Add wells one at a time with Add well. Import wells adds many at once from a CSV file, a zipped shapefile, a GeoJSON file or a KML file.{% else %}Run the import_wells command on the server with a CSV file or a shapefile to load your wells.{% endif %} Each well needs a name and a location.

{{ steps.stations }}Connect monitoring stations Sources and monitoring > Monitoring Stations
Go to Monitoring Stations →		 {% if 'setup' in enabled_modules %}The Setup Wizard adds the stations it finds near your boundary and leaves syncing off for each one. {% endif %}Switch syncing on for each station you want to follow, or add a station with Add station. OpenH2O then collects new readings from those stations on your server’s schedule, or at once with Update readings now on the station’s page. You enter each reading on the station’s page for a station added as Entered by hand.
{{ steps.accounts }}Set up water accounts Water accounting > Accounts
Go to Accounts →		 Create a water account for each farm unit{% if 'surface' in enabled_modules %}, place of use or water right{% else %} or place of use{% endif %} you track. Use Import accounts on the Accounts page to import the accounts from a spreadsheet. Use + Add account to add one account. Assign its use areas on the account’s page after you create it.
{{ steps.water_year }}Create a water year Water accounting > Water Years
Go to Water Years →		 Create each water year with its start and end dates. A water year starts on the first day of a month and ends on the last day of a month. Set your water year’s start month on Delivery Settings before you set the first allocation ceiling. The default is October.
{{ steps.ceilings }}Set allocation ceilings Water accounting > Allocations
Go to Allocations →		 Set an allocation ceiling in acre-feet for each zone, water type and water year.
{{ steps.ledger }}Record water use Water accounting > Use Ledger
Go to Use Ledger →		 Record meter readings, deliveries and adjustments one at a time with Add ledger entry, or many at once with Upload CSV. OpenH2O files each entry under the water year that includes its date. OpenH2O counts an entry as groundwater only in three cases: its water type is groundwater, it is a Meter Reading with no water type, or its source type is Calculated. OpenH2O calculates each month’s figures for a water year when you press Run the calculation on that water year’s page. It also calculates them every night once your server’s scheduled jobs are installed.{% if 'wells' in enabled_modules %} A use area can have a well and no meter reading. OpenH2O enters that use area’s ETAW met by groundwater on the Use Ledger.{% endif %}

Correcting a record

Choose Correct this record in a record’s ... menu. Enter the new figure and a reason and attach any photo or PDF. The old record stays on its page struck through with a line naming its replacement.{% if 'accounting' in enabled_modules %} OpenH2O recalculates the months affected. Only an administrator can correct a record in a finalized water year.{% endif %}

{% if 'accounting' in enabled_modules %}

Figures as filed

OpenH2O keeps a copy of a water year’s figures when an administrator finalizes it. The Figures as filed section of the water year page lists the figures that have changed since then and the corrections behind them. Reopening the year keeps that copy, and finalizing it again records the restated figures.

Changes to this year’s records

A finalized water year’s page shows whether the records its code covers have changed since the code was issued. Check for changes computes the code again and counts the corrections recorded since. The Download a copy to keep link saves a one-page file.
