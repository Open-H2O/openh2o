# The page pass, 2026-09

*Written 2026-09-06 by Phase 137, Plan 03 of milestone v2.16 "Every Figure Traced".*

Every rendered page of the platform, one line each: what the screen is for, the one
figure it leads with, and what the reader leaves with. Phase 135 traced every figure
to its rows; this table is the other half of ISS-150's second question, whether every
page is organised, and it is the first time the purpose of each screen has been
written down page by page. Phase 138's presentation pass polishes these pages knowing
what each one is for.

## The census

```
find templates -name "*.html" | grep -v "/partials/" | wc -l        # 83
# minus the three layout shells: templates/base.html, base_auth.html, workspace.html
# = 80 rows below
grep -rn "path(" */urls.py | wc -l                                  # 131 route declarations, 15 files
```

**80 pages, 3 shells noted.** One of the 80, `allauth/layouts/base.html`, is in fact
a fourth layout shell; it is kept as a row, marked as such, because the census
definition above is what the count reproduces from. Non-page routes are excluded by
kind, not one by one: GeoJSON feeds, HTMX partials swapped into a page, toggles and
other POST-only actions, redirects, file downloads and the health probes. The
census with each page's route, view, pinned URL and slice is
`.planning/phases/137-water-balance-panel-and-page-pass/137-03-census.json`.

Every page was loaded as served. Sixty-eight were fetched signed in through the
platform's own authenticated client (`scripts/figure_capture.py`, the figure ledger's
capture path), eleven signed out through Caddy on port 80 (the sign-in, sign-up and
password pages, and the front page's anonymous branch). Two answered 302 rather than
200, `/setup/confirm/` and `/setup/run/`, because neither has a wizard session to
read; the rows describe the page from its template and view and say so. Four
sub-agents each read one slice (rendered page plus template plus view) and proposed a
row; the verdicts below were decided by the orchestrator against the rule, and a
sample of ten rows was then checked by one clean agent with no history (the ratio is
in `137-03-EVIDENCE.md`).

## The columns

- **Purpose** — one clause: who opens this page and to do what. If the honest answer
  is "to get to another page", it says so; a router page is a legitimate purpose.
- **Lead figure** — the ONE number, record or map the page exists to produce (the thing
  a `.result-card` would hold). "none" is a valid answer for a form or a list;
  "several, none leads" is a finding.
- **What leaves** — what the reader carries away or does next: a figure they act on, a
  file they download, the one link they follow. A page with no exit but the browser's
  back button is a finding.
- **Verdict** — `KEEP`, `CHANGE: ISS-###` (an issue already filed), `CHANGE: small`
  (one template or one view, fixed in this plan), `CHANGE: file` (larger; filed with a
  re-entry condition). A row changes only when the screen fails ITS OWN line: a purpose
  it does not serve, a lead figure it buries or lacks, an exit it does not offer.
  Aesthetics, casing, rounded corners and four-decimal volumes are Phase 138's
  (ISS-149, ISS-142) and do not make a row change here.

The **c#** column is the page's number in the census file, for tracing a row back to
the slice that proposed it.

## What the pass found

- **Three rows out of eighty change, and two of them were known before the pass
  began.** The one new finding is a sentence: the Allocations page promised a
  comparison it has never drawn. The other seventy-seven screens serve the purpose
  written beside them, lead with the figure or the record they exist to produce, and
  offer a real way out.
- **"Several, none leads" is the honest answer on eleven pages, and on ten of them it
  is by design.** Finder lists (wells, use areas, diversion points, water rights,
  recharge sites, zones), the front page's signed-out branch, the drinking-water front
  door, the monitoring dashboard and the report list are routers: their job is to get
  the reader to the page that has the figure. The use ledger's two deliberately
  un-netted subtotals (ISS-155) are the eleventh. Fifty-four pages answer "none": forms,
  settings, help and account pages, which is the right answer for each of them.
- **Two known issues are closed by rendering, not by rewording.** The well page's
  description sentence is unchanged; the record it promised now sits under it. The
  basin readings' notes are on screen.
- **Nothing here is a Phase 138 matter, and Phase 138 matters were kept out.** Where
  a sub-agent proposed a change for casing, spacing or decimals it was demoted to
  KEEP with the phase named in the note; none survived to the table above.
- **One pinned-instance artifact and one demo-content gap, both KEEP.** Station 1 has
  never synced, so its chart and records show honest empty states; no reporting period
  in the demonstration carries OpenET rows for the prefill page because that sync is
